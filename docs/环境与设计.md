# 环境与设计

程序要求 Python 3.10+、Git 2.23+，仅依赖 Python 标准库。平台与验证范围见[验证记录](验证记录.md)，安装及操作见[README](../README.md)。

## 数据布局

默认配置目录为 `~/.skills-sync`，可通过 `--config` 或 `SKILLS_SYNC_CONFIG` 指定其他配置文件。

```text
config.json       当前设备的目录、远端和过滤配置
hub/              私有数据仓库的本机 Git 工作区
  skills/<id>/    过滤后的完整 skill 文件
  manifest.json   身份、来源、哈希及全局删除记录
state/            本机基线、安装映射、偏好、冲突、备份和操作记录
```

仅共享库进入数据仓库；每台设备独立保存配置和 state。程序发布仓库与用户的数据仓库分开。

## 同步与冲突

CLI `plan` 先获取远端，比较共同基线、本机内容和远端内容，输出下一步动作。`sync` 更新共享库并推送，之后部署本机变化；成功完成后再记录新基线。文本改动无重叠时可合并，无法确定的文本、二进制或删除与修改冲突保留快照，由用户决定。

批准及执行绑定输入版本。计划生成、备份、准备替换或冲突批准之后出现新编辑时，工具会检查版本并拒绝用旧内容覆盖。目录替换会保留旧目录以便失败回退；恢复也先准备和校验副本，再检查目标版本。

本机卸载与全局删除是不同的操作：前者写本机不安装偏好，后者向共享库写删除记录并传播。上游更新由用户另行处理。

## 边界

默认排除系统目录、缓存和常见凭据；符号链接与 Windows junction 不跟随。复制时检查源及目标的路径链。过滤不能证明内容一定没有敏感信息，用户应检查纳入范围并使用私有数据仓库。

网络失败、部分部署、过期批准和未确认远端均通过退出码及结构化输出区分。不要手工修改 state 或用强制 Git 操作替代同步流程。
